## 1. 数据采集模块（`simulator/`）

用例图：`docs/03-建模/02-用例图-数据采集.puml`

### UC-01 生成闸机事件

| 项 | 内容 |
|----|------|
| 参与者 | 系统维护者 |
| 优先级 | 高 |
| 前置条件 | Redis 可用；Stream `gate_events` 已存在或允许自动创建 |
| 基本流 | 1. 维护者启动模拟器<br>2. 系统取当前时刻，判断所处时段<br>3. 按站点权重选一个站，按时段决定进/出站倾向<br>4. 生成 1—5 人的乘客数，组装成契约 2.1 的事件<br>5. 写入 Stream，打印一条日志<br>6. 按速率等待后回到步骤 2 |
| 备选流 | A1 指定 `--count` 时，达到条数即退出 |
| 异常流 | E1 连不上 Redis：提示先启动容器并退出，不无限重试 |
| 后置条件 | Stream 中新增一条符合契约的事件 |

### UC-02 设置发送速率与数量

| 项 | 内容 |
|----|------|
| 参与者 | 系统维护者 |
| 优先级 | 中 |
| 前置条件 | 无 |
| 基本流 | 1. 维护者传 `--speed`（倍速）与 `--count`（条数）<br>2. 系统按 `1/speed` 换算发送间隔<br>3. `--count` 为 0 时表示不限条数 |
| 异常流 | E1 `--speed` 非正数：按 0.01 兜底，避免除零或死循环 |
| 后置条件 | 发送节奏与参数一致 |

### UC-03 注入异常数据

| 项 | 内容 |
|----|------|
| 参与者 | 系统维护者 |
| 优先级 | 高 |
| 前置条件 | 已设置 `--inject` 比例（0—1） |
| 基本流 | 1. 每条事件生成后按比例抽样<br>2. 命中时随机选一种异常：缺字段（去掉 `passengers` 或 `event_time`）或乱序（事件时间回拨 3—30 秒）<br>3. 照常写入 Stream |
| 异常流 | E1 `--inject` 超出 0—1：参数校验直接报错退出 |
| 后置条件 | 消费端能统计到 `invalid_count` / `late_count`，链路不中断 |

### UC-04 回放历史样例

| 项 | 内容 |
|----|------|
| 参与者 | 系统维护者 |
| 优先级 | 中 |
| 前置条件 | 样例文件存在且为 JSONL，每行一条事件 |
| 基本流 | 1. 维护者传 `--replay <路径>`<br>2. 系统读取全部事件<br>3. 按事件时间差与倍速计算等待时长<br>4. 逐条写入 Stream |
| 异常流 | E1 文件为空：提示后结束<br>E2 某行不是合法 JSON：读文件阶段即失败退出 |
| 后置条件 | 同样的样例两次回放得到同样的指标序列 |

## 2. 实时计算模块（`stream/`）

用例图：`docs/03-建模/03-用例图-实时计算.puml`；活动图：`06`、`07`

### UC-05 消费事件

| 项 | 内容 |
|----|------|
| 参与者 | 计算进程（主）、系统维护者（启停） |
| 优先级 | 高 |
| 前置条件 | Redis 可用；消费组 `metric_builder` 已建立（不存在则创建） |
| 基本流 | 1. 进程启动，`ping` 通过后建立消费组<br>2. 以消费组身份读取新消息（`>`）<br>3. 逐条取出 `data` 字段解析为事件<br>4. 交给窗口处理<br>5. 处理完成后确认（ACK）消息 |
| 备选流 | A1 无新消息：阻塞等待，超时后进入下一个窗口 |
| 异常流 | E1 消息体不是合法 JSON：按一条非法事件处理，仍要 ACK，避免卡在待确认列表<br>E2 Redis 中途断开：记录日志后退出，由运维重启 |
| 后置条件 | 已处理的消息进入确认状态，未处理的下次可重投 |

### UC-06 窗口聚合出指标

| 项 | 内容 |
|----|------|
| 参与者 | 计算进程 |
| 优先级 | 高 |
| 前置条件 | 已读入若干事件 |
| 基本流 | 1. 取当前时刻并向下对齐到整秒，得到窗口起点<br>2. 计算窗口结束时间<br>3. 把事件分成"本窗口"和"属于后续窗口"两部分<br>4. 后续窗口的事件暂存，留到下一轮<br>5. 对剩余事件按站点累加客流，同时统计迟到、非法<br>6. 站点结果按客流降序排列 |
| 备选流 | A1 本窗口没有有效事件：仍产出全 0 的指标，用于维持快照存活 |
| 异常流 | E1 暂存队列超过上限：只保留最近的一批，防止内存被异常数据撑爆 |
| 后置条件 | 得到含 `total`、`stations`、`late_count`、`invalid_count` 的指标对象 |

### UC-07 判定迟到与非法事件

| 项 | 内容 |
|----|------|
| 参与者 | 计算进程 |
| 优先级 | 高 |
| 前置条件 | 事件已进入聚合流程 |
| 基本流 | 1. 尝试解析 `event_time`、`passengers`、`station_id`<br>2. 任一字段缺失或类型不对，计一条非法并跳过<br>3. 事件时间早于"窗口起点减 2 个窗口"，计一条迟到并跳过<br>4. 其余事件计入客流 |
| 备选流 | A1 迟到事件按站点记录，写入数据库时带在对应站点行上 |
| 异常流 | E1 时间字符串格式不合法：等价于缺失，计非法 |
| 后置条件 | 三个计数之和与输入事件数一致（除未来窗口事件外） |

### UC-08 写快照与写入数据库

| 项 | 内容 |
|----|------|
| 参与者 | 计算进程 |
| 优先级 | 高 |
| 前置条件 | 指标已算出 |
| 基本流 | 1. 组装快照 JSON（含时间戳、总量、站点明细、两个计数）<br>2. 写入 `metric:snapshot`，设置 5 秒过期<br>3. 按站点组装明细行<br>4. 批量写入 `metric_window`，冲突时忽略 |
| 备选流 | A1 本窗口没有任何站点数据：跳过写入数据库 |
| 异常流 | E1 数据库不可用：只告警一次，继续写快照，实时功能不受影响 |
| 后置条件 | 快照可被接口读到；明细可按窗口查询；重放同一窗口不产生重复行 |

### UC-09 重启后续消费

| 项 | 内容 |
|----|------|
| 参与者 | 计算进程、系统维护者 |
| 优先级 | 中 |
| 前置条件 | 进程曾异常退出或被人为停止 |
| 基本流 | 1. 重新启动，加入同一消费组<br>2. 组内记录上次确认位置<br>3. 只读取未确认的消息<br>4. 重新聚合写入，唯一键保证不产生重复行 |
| 备选流 | A1 重启期间到达的新消息按正常路径消费 |
| 异常流 | E1 停机超过快照有效期：页面先显示暂无数据，恢复后自动续上 |
| 后置条件 | 重启前后的累计客流连续，无重复 |

## 3. 数据服务模块（`api/`）

用例图：`docs/03-建模/04-用例图-数据服务.puml`

### UC-10 获取实时快照

| 项 | 内容 |
|----|------|
| 参与者 | 大屏页面、值班员 |
| 优先级 | 高 |
| 前置条件 | Web 服务运行 |
| 基本流 | 1. 调用方请求 `/api/snapshot`<br>2. 服务读取 `metric:snapshot`<br>3. 有值则原样返回，响应头带 `no-store` |
| 备选流 | A1 快照不存在（消费者未启动或已停）：返回空结构，状态码仍为 200 |
| 异常流 | E1 Redis 不可用：同样返回空结构，不让页面报错<br>E2 快照内容不是合法 JSON：按空结构处理 |
| 后置条件 | 调用方拿到与契约一致的结构 |

### UC-11 查询历史序列

| 项 | 内容 |
|----|------|
| 参与者 | 主管、大屏页面 |
| 优先级 | 中 |
| 前置条件 | `metric_window` 中已有数据 |
| 基本流 | 1. 请求 `/api/series`，可带 `station_id` 与 `minutes`<br>2. 校验 `minutes` 为 1—60 的整数<br>3. 按起始时间过滤，指定站则加站点条件<br>4. 按时间戳聚合后升序返回 |
| 备选流 | A1 不传 `station_id`：按时间戳汇总全部站点 |
| 异常流 | E1 参数非法：返回 400 与 `INVALID_PARAM`，消息里带上收到的值 |
| 后置条件 | 返回点序与落库粒度一致（每秒一个点） |

### UC-12 查询站点排行

| 项 | 内容 |
|----|------|
| 参与者 | 主管、大屏页面 |
| 优先级 | 中 |
| 前置条件 | `metric_window` 中最近 5 分钟有数据 |
| 基本流 | 1. 请求 `/api/rank`，可带 `top`<br>2. 校验 `top` 为 1—20 的整数，缺省 5<br>3. 取最近 5 分钟数据，按站点求和<br>4. 降序取前 N 返回 |
| 异常流 | E1 参数非法：400 + `INVALID_PARAM` |
| 后置条件 | 排行数值与历史序列同期累计一致 |

### UC-13 渲染大屏页面

| 项 | 内容 |
|----|------|
| 参与者 | 值班员 |
| 优先级 | 高 |
| 前置条件 | Web 服务运行 |
| 基本流 | 1. 浏览器请求 `/`<br>2. 服务端渲染页面模板并返回<br>3. 浏览器加载 CDN 上的 Vue 与 ECharts，接管页面 |
| 异常流 | E1 模板语法错误：返回 500，由服务端日志定位 |
| 后置条件 | 页面与接口同源，无需跨域配置 |

## 4. 可视化展示模块（`web/`）

用例图：`docs/03-建模/05-用例图-可视化展示.puml`；活动图：`08`

### UC-14 查看实时客流

| 项 | 内容 |
|----|------|
| 参与者 | 值班员 |
| 优先级 | 高 |
| 前置条件 | 页面已打开，接口可用 |
| 基本流 | 1. 页面每秒请求一次快照<br>2. 更新顶部总客流与站点明细<br>3. 柱状图重绘，站点按客流降序 |
| 备选流 | A1 快照为空：图表留空并显示"暂无数据" |
| 异常流 | E1 请求失败：转入 UC-18 |
| 后置条件 | 页面数据时间与最新窗口一致 |

### UC-15 按线路筛选

| 项 | 内容 |
|----|------|
| 参与者 | 值班员 |
| 优先级 | 中 |
| 前置条件 | 已有站点明细，且每条明细带 `line_id` |
| 基本流 | 1. 点击"1 号线/2 号线/全部"<br>2. 页面按线路过滤站点集合<br>3. 柱状图只画过滤后的站点 |
| 备选流 | A1 某线路当前无数据：图表为空但保留坐标轴 |
| 后置条件 | 筛选状态在下次刷新后保持 |

### UC-16 查看趋势与排行

| 项 | 内容 |
|----|------|
| 参与者 | 主管 |
| 优先级 | 中 |
| 前置条件 | 历史数据可用 |
| 基本流 | 1. 页面每 5 秒请求一次序列与排行<br>2. 序列渲染为折线，排行渲染为列表<br>3. 两者与柱状图共用同一口径 |
| 备选流 | A1 历史接口失败：保留上一轮图形，不打断主看板 |
| 后置条件 | 趋势时间窗为最近 5 分钟 |

### UC-17 接收客流告警

| 项 | 内容 |
|----|------|
| 参与者 | 值班员 |
| 优先级 | 高 |
| 前置条件 | 页面在刷新中 |
| 基本流 | 1. 每次拿到快照后比较总客流与阈值<br>2. 超过阈值显示红色横幅，文案带上当前值与阈值<br>3. 回落到阈值以下自动消失 |
| 备选流 | A1 阈值暂为前端常量 100 人次/秒，待配置化 |
| 后置条件 | 告警状态与最近一次快照一致 |

### UC-18 感知断线与恢复

| 项 | 内容 |
|----|------|
| 参与者 | 值班员 |
| 优先级 | 高 |
| 前置条件 | 页面在轮询 |
| 基本流 | 1. 请求超时或返回非 2xx<br>2. 底部状态变为"连接中断，正在重试"<br>3. 定时器继续按周期重试<br>4. 恢复后状态回到"实时连接"，数据自动续上 |
| 异常流 | E1 长时间断线：页面保留最后一次数据，但明确标注不是最新 |
| 后置条件 | 无需人工刷新页面 |

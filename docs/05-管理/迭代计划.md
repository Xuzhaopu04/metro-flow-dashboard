# 迭代计划

四个 Sprint，每个 1—2 周，对应实验一至实验四。每个 Sprint 结束必须有一个能演示的增量，不接受"只差联调"。

## Sprint 1 · 实验一：需求分析与迭代规划

| 项 | 内容 |
|----|------|
| 目标 | 说清楚要做成什么样，边界在哪 |
| 任务 | 选题确认与场景调研；角色与故事梳理；非功能指标定义；四个 Sprint 排期；仓库与看板就位 |
| 产出 | `docs/01-需求/用户故事地图.md`、`docs/01-需求/用例表.md`、`docs/03-建模/01-用户故事地图.puml`、四张分模块用例图（`02`～`05`）、三张活动图（`06`～`08`）、看板与任务卡 |
| 验收 | 每条需求能对上一条故事；非功能指标可测量 |

## Sprint 2 · 实验二：系统设计与技术选型

| 项 | 内容 |
|----|------|
| 目标 | 定下架构、接口与数据模型，后面不再大改 |
| 任务 | 架构方案比较与论证；接口契约冻结；指标口径定义；数据模型与迁移；设计阶段 UML |
| 产出 | `docs/02-设计/` 三份文档、`docs/03-建模/09-数据流图.puml`、`10-类图.puml`、`11-时序图.puml`、`12-部署图.puml`、`api/migrations/0001_initial.py` |
| 验收 | 契约字段与类图一一对应；换个组员看文档能说出数据怎么流 |

## Sprint 3 · 实验三：原型构建与实现

| 项 | 内容 |
|----|------|
| 目标 | 端到端跑通，能当演示 |
| 任务 | 采集（限速/限量/异常注入/回放）；计算（消费组、切窗、落库）；服务（三个接口 + 参数校验）；前端（柱状图、筛选、排行、趋势、断线提示）；联调 |
| 产出 | 四个目录的可运行实现、`tests/` 用例、`scripts/dev_up.sh`、演示脚本 |
| 验收 | 从造数到上屏 2 秒内；`--inject 0.1` 连跑 10 分钟不崩 |

## Sprint 4 · 实验四：测试与部署

| 项 | 内容 |
|----|------|
| 目标 | 用证据说明它能用，别人能照着部署 |
| 任务 | 测试方案与用例；执行并留痕；缺陷记录与回归；部署方案；报告成稿；互评 |
| 产出 | `docs/04-测试/`、部署说明、实验报告、`docs/05-管理/组内互评表.md` |
| 验收 | 他人按部署说明从零跑通一次；用例全部有结论 |

## 分工

| 角色 | 负责目录 | 主要任务卡 |
|------|----------|-----------|
| 采集 | `simulator/` | US-01、US-02、US-09 |
| 计算 | `stream/` | US-03、US-06、数据质量计数 |
| 服务 | `api/`、`config/` | 三个接口、参数校验、错误结构 |
| 前端 | `web/` | US-04、US-05、US-07、US-08 |
| 文档（兼） | `docs/` | 契约、口径、建模、测试、报告 |

## 节奏

- 每天在群里同步一次"昨天做了什么、今天做什么、卡在哪"；
- 任务卡移动状态即进度，不另做表格；
- 每个 Sprint 末开一次评审，当场演示，不通过就顺延到下一轮并记下来。

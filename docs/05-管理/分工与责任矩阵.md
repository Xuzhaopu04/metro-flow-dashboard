# 分工与责任矩阵

> 定这份文件的原因：README 里的表只到"目录"粒度，出问题时不够用——同一个目录里谁改哪个文件、
> 谁的模块谁补测试、改动别人目录要怎么办，这些必须在开工前说死，否则联调时全是口角。

## 一、分工原则

1. **按目录切，不按功能切。** 功能必然跨模块（"排行"要动 stream、api、web 三个目录），但文件不能两人同时改。
2. **一人一段数据流。** 采集→计算→服务→展示，每段一个人从头负责到尾。
3. **接口由契约固定。** 跨目录只通过 `docs/02-设计/接口契约.md` 约定的字段通信，不靠口头对齐。
4. **自己的模块自己测。** 谁的代码谁补用例，不留给别人兜底。

## 二、责任矩阵

| 角色 | 目录与文件 | 负责什么 | **不**负责什么 |
|------|-----------|----------|---------------|
| 采集 | `simulator/simulator.py`<br>`simulator/stations.json`（待建） | 站点表与客流权重、早晚高峰分布、事件生成、`--inject` 异常注入、`--replay` 回放、命令行参数 | 消息如何被消费、指标怎么算 |
| 计算 | `stream/metrics.py`<br>`stream/consumer.py` | 窗口对齐与切分、跨窗口事件处理、按站聚合、迟到与非法判定、Top-N、消费组、快照写入、按站落库 | 接口怎么暴露、页面怎么画 |
| 服务 | `api/models.py` `api/views.py` `api/urls.py`<br>`api/migrations/` `config/` | 数据模型与迁移、三个接口、参数校验、统一错误结构、环境变量配置 | 指标算法、页面渲染样式 |
| 前端 | `web/index.html` | 大屏页面：柱状图、线路筛选、排行、趋势、告警横幅、断线提示 | 数据怎么算、接口怎么实现 |
| 队长 | `docs/` 全部<br>`README.md` `AGENTS.md` `requirements.txt` `docker-compose.yml` | 契约与口径、UML、测试方案、报告统筹、PR review 与合并、看板与互评 | 代替组员写他模块的代码 |

### 各角色对应的报告章节

|------|----------|

## 三、测试与用例归属

| 测试文件 | 覆盖 | 归属 |
|----------|------|------|
| `tests/test_metrics.py` | 窗口切分、口径计算、迟到与非法 | 计算 |
| `tests/test_consumer.py` | 消息解析、脏数据容错、消费组 | 计算 |
| `tests/test_api.py` | 三个接口、参数校验、404 结构 | 服务 |

新增测试放对应文件；跨模块的集成用例由队长补，放 `tests/test_integration.py`（待建）。

## 四、四个接口点（跨目录只在这里碰面）

| 接口点 | 内容 | 谁定 | 谁写 | 谁读 | 变更找谁 |
|--------|------|------|------|------|----------|
| ① 消息格式 | `GateEvent` 六个字段 | 队长（契约 2.1） | 采集 | 计算 | 队长 |
| ② 快照结构 | `metric:snapshot` 的 JSON | 队长（契约 3） | 计算 | 服务 | 队长 |
| ③ 三个接口 | snapshot / series / rank | 队长（契约 4） | 服务 | 前端 | 队长 |
| ④ 告警阈值 | 阈值放在哪、谁判定 | 服务 + 前端协商 | 服务 | 前端 | 服务 ↔ 前端 |

**除这四处之外，任何跨目录改动都要先提 issue 说明理由。**

## 五、改别人目录怎么办

| 情形 | 做法 |
|------|------|
| 发现别人模块有 bug | 提 issue，@ 对方，**不要直接改** |
| 需要别人模块配合改动 | 提 issue 写清输入输出，对方排期 |
| 对方请假或卡住，队长代改 | 队长可以改，但必须在 issue 里写明"代改"，并请对方事后 review |
| 紧急线上问题（演示前） | 队长直接修，事后补 issue 留痕 |

## 六、每人交付清单（除代码外）

1. 自己模块的单元测试，`pytest` 全绿；
2. 自己模块的实现说明 2—3 段，直接进报告第三部分；
3. 自己模块相关的图：计算交活动图、服务交时序图、前端交页面交互说明；
4. `docs/05-管理/AI使用记录.md` 里自己的条目，当天记；
5. 互评依据：自己名下的提交与已合并 PR。

## 七、人数调整

| 人数 | 调整 |
|------|------|
| 4 人 | 队长兼服务层（`api/` + `config/`），其余三人分采集、计算、前端 |
| 5 人 | 第五人负责 `docs/` 与报告第一、二部分，不占代码目录，不与人冲突 |

## 八、答辩口径

- 被问到**别人的模块**：说明"这块由某某负责，我只清楚与它对接的接口"，然后把契约字段说清楚；
- 被问到**自己的模块**：必须能解释每一处设计取舍，包括为什么不选另一种写法。

# 组内互评表

按实验报告第五章要求填写。四个阶段各 100 分，最终换算成个人贡献系数（人均为 1）。

## 1. 评分表

| 姓名 | 需求分析 | 系统设计 | 系统实现 | 系统测试 | 合计 |
|------|---------|---------|---------|---------|------|
|  |  |  |  |  |  |
|  |  |  |  |  |  |
|  |  |  |  |  |  |
|  |  |  |  |  |  |
| 合计 | 100 | 100 | 100 | 100 | — |

## 2. 贡献系数算法

1. 每人四阶段得分相加，得到个人总分；
2. 全组个人总分的平均值为基准；
3. 个人总分 ÷ 基准 = 个人贡献系数，保留一位小数；
4. 系数之和应等于组内人数，用来校验算错没有。

## 3. 评分依据

打分必须能指到证据，否则不予采信：

| 阶段 | 看什么 |
|------|--------|
| 需求分析 | 故事地图与需求文档的提交记录、评审意见 |
| 系统设计 | 契约与 UML 的作者、设计评审发言 |
| 系统实现 | 该成员名下的提交、PR、代码行与难度 |
| 系统测试 | 用例编写与执行记录、缺陷发现数 |

产出目录见 `docs/05-管理/迭代计划.md` 的分工表。

## 4. 说明

- 由组长组织，先自评再互评，最后组长核定；
- 结果组内公示，被评人可申诉一次，组长需书面说明异常分值的原因；
- 不以提交行数作为唯一依据：写文档、做联调、抓缺陷同样计入贡献。

契约 v1.3 加法清单

只加不删；旧字段、旧参数、旧测试必须继续通过
接口 / 存储 变更 兼容策略 谁写 / 谁读
/api/series 新增 line_id、direction、granularity、from/to；点结构增加 in/out/total。 保留 minutes / station_id；默认行为不变；最大点数 2000。 服务写 / 前端读
/api/rank 新增 minutes、line_id、direction。 默认仍为最近 5 分钟；旧调用不传参不受影响。 服务写 / 前端读
/api/summary/today 新增接口：今日累计、进/出、峰值、分线/分站 TopN、数据质量、更新时间。 全新接口，不影响旧接口；必须注明统计起点。 服务写 / 前端读
/api/stations 新增接口：站点名称、线路、顺序、坐标、颜色。 只读采集的 stations.json，不复制数据。 服务写 / 前端读
metric_window 新增 in_passengers、out_passengers 两列。 可空/默认 0；先迁移、再双写、后切读；(ts, station_id) 唯一不变。 计算写 / 服务读
消息格式 不变；现有 event_type 已能区分进/出站。 不动 gate_events，采集和计算不需要改消息契约。 采集写 / 计算读
口径提醒：当前 total 是“进站 + 出站”的乘降量，不是去重客流。一个乘客进站、出站会被计两次。页面必须写清“乘降量 / 进站量 / 出站量 / 净流入”，不要笼统叫“客流”。数据里没有 card_id / trip_id，本期不做 OD 和断面。

联调与验收清单

Definition of Done：代码 + 测试 + 文档 + 演示 + AI 记录

前端交付前

  • v1.3 字段冻结，变更记录已写
  • mock 覆盖正常 / 空 / 降级 / 错误 / 过期
  • 旧 pytest 全绿，新契约测试全绿
  • in + out = total 有页面级校验
  • 60 分钟 1 秒、24 小时 1 分钟不卡
  • CSV 可导出，URL 可复现查询
  • 关键路径截图 + 交互说明
  • AI 使用记录当天补

主要风险与应对

  • 后端延迟：先发 Slice 0，不阻塞演示；Slice 1 用 mock 顶住。
  • 契约反复：Sprint 边界冻结；mock 确定后不再改字段名。
  • 历史数据不足：采集补 backfill，否则查询页没东西可查。
  • 口径误解：页面固定写“乘降量”，不要只写“客流”。
  • 数据库不可用：沿用现有降级模式，返回空结构 200，不白屏。

# 指标口径

> 这份文档比字段定义更重要：字段错了会报错，口径错了会算出"看着对其实是错"的数。
> 代码实现见 `stream/metrics.py`，可执行的版本见 `tests/test_metrics.py`。

## 1. 窗口

- 长度 1 秒（`WINDOW_SECONDS`），按**处理时间**触发，窗口起点向下对齐到整秒。
- 窗口标签 `ts` 用的是窗口起点，精确到秒，带时区（`+08:00`）。
- 同一批读回来的事件如果跨了窗口，晚于当前窗口结束时间的部分留到下一轮算，避免把下一秒的客流提前计入。见 `split_ready()`。

## 2. 指标

| 指标 | 定义 | 计算 | 单位 |
|------|------|------|------|
| `total` | 当前窗口新增客流 | 窗口内所有事件 `passengers` 求和 | 人次 |
| `stations[].passengers` | 该站当前窗口新增客流 | 按 `station_id` 分组求和 | 人次 |
| `late_count` | 迟到事件数 | 事件时间早于窗口起点 2 个窗口以上 | 条 |
| `invalid_count` | 非法事件数 | 缺必填字段、类型不对、JSON 解析失败 | 条 |
| `rank` | 站点排行 | 最近 5 分钟按站求和后降序取前 N | — |
| `points` | 历史序列 | `metric_window` 按 `ts` 聚合（指定站则只取该站） | 人次 |

**不是累计值**：`total` 每秒清零重算。要展示"今日累计"另立字段，不要复用这个。

## 3. 边界规则

| 情形 | 处理 | 理由 |
|------|------|------|
| 事件时间比窗口起点早 1 秒内 | 正常计入 | 网络与时钟误差在容差内 |
| 事件时间比窗口起点早 2 秒以上 | 计入 `late_count`，不计入客流 | 迟到数据混进来会让当前秒虚高 |
| 事件时间晚于窗口结束 | 留给下一轮 | 同上，方向相反 |
| 缺 `passengers` / `event_time` | 计入 `invalid_count` | 无法判断该算多少 |
| `passengers` 不是整数 | 计入 `invalid_count` | 口径要求整数，不做隐式转换 |
| `line_id` 缺失 | 该站 `line_id` 记为 `""` | 不影响客流统计，只影响线路筛选 |
| 整条消息 JSON 坏了 | 计一条 `invalid_count` | 消费者不能因为一条脏数据停摆 |

## 4. 一致性约束

- 同一窗口内：`total == sum(stations[].passengers)`。
- `late_count + invalid_count` 与 `total` 无换算关系，三者独立。
- 落库每站每窗口一行，`(ts, station_id)` 唯一；重放同一窗口不会产生重复行。
- 快照 TTL 5 秒：消费者停超过 5 秒，接口就会返回空结构，页面应表现为"暂无数据"而不是报错。

## 5. 已知简化

- 窗口按处理时间切分，不是严格的事件时间窗口；时钟偏差超过 2 秒的事件会被判成迟到。
- 迟到事件只计数，不回补历史窗口（见任务卡"迟到事件回补"）。
- 进站与出站目前合并统计（契约待定问题 3）。

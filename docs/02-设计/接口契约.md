## 1. 通用约定

| 项 | 约定 |
|----|------|
| 编码 | UTF-8 |
| 时间 | ISO8601 字符串，精确到毫秒（快照 `ts` 精确到秒），带时区 |
| 时间语义 | `event_time` 是事件发生时间，不是入库时间 |
| 数值 | 人数、条数一律整数 |
| 空值 | `null` |
| 命名 | 小写下划线，前端不做字段名转换 |
| 返回体 | 一律 JSON 对象，不直接返回数组 |
| 错误体 | `{"error": {"code": "...", "message": "..."}}` |

## 2. 消息格式（Redis Stream）

键名 `gate_events`，写入方 `simulator/simulator.py`，消费组 `metric_builder`（`stream/consumer.py`）。
消息体单字段 `data`，值为 JSON 字符串。

### 2.1 闸机事件

| 字段 | 类型 | 必填 | 示例 | 说明 |
|------|------|------|------|------|
| `event_id` | string(uuid) | 是 | `9515820e-...` | 全局唯一，用于去重 |
| `station_id` | string | 是 | `A01` | 站点编码 |
| `line_id` | string | 是 | `L1` | 线路编码 |
| `event_type` | string | 是 | `in` / `out` | 进站或出站 |
| `passengers` | int | 是 | `2` | 本条记录的乘客数，1—5 |
| `event_time` | string | 是 | `2026-10-20T09:30:15.123+08:00` | 事件发生时间 |

### 2.2 异常数据约定

模拟器 `--inject` 会掺两类，消费端**必须处理而不是崩溃**：

| 类型 | 表现 | 期望处理 |
|------|------|----------|
| 缺字段 | 缺 `passengers` 或 `event_time` | 跳过并计入 `invalid_count` |
| 乱序 | `event_time` 早于当前窗口 | 计入 `late_count`，不计入当前窗口 |

## 3. 存储约定

| 键 / 表 | 类型 | 写入方 | 读取方 | 说明 |
|---------|------|--------|--------|------|
| `gate_events` | Redis Stream | 模拟器 | 消费者 | 事件队列，保留最近 10 万条 |
| `metric:snapshot` | Redis String | 消费者 | 接口 | 最新快照 JSON，TTL 5 秒 |
| `metric_window` | MySQL 表 | 消费者 | 接口、对账 | 每站每窗口一行，`(ts, station_id)` 唯一 |

快照结构：

```json
{
  "ts": "2026-10-20T09:30:15+08:00",
  "total": 37,
  "stations": [
    {"station_id": "A01", "line_id": "L1", "passengers": 12},
    {"station_id": "A02", "line_id": "L1", "passengers": 9}
  ],
  "late_count": 1,
  "invalid_count": 0
}
```

## 4. REST 接口

### 4.1 最新快照

```
GET /api/snapshot
```

成功 200，返回上面的快照结构。**无数据时也返回 200**，结构如下（不要返回 404）：

```json
{"ts": null, "total": 0, "stations": [], "late_count": 0, "invalid_count": 0}
```

响应头带 `Cache-Control: no-store`。

### 4.2 历史序列

```
GET /api/series?station_id=A01&minutes=5
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| `station_id` | string | 否 | 全部 | 不传则按时间汇总所有站点 |
| `minutes` | int | 否 | 5 | 回溯范围，1—60 |

```json
{"station_id": "A01", "points": [{"ts": "2026-10-20T09:30:15+08:00", "passengers": 12}]}
```

### 4.3 站点排行

```
GET /api/rank?top=5
```

统计窗口固定为最近 5 分钟，`top` 取 1—20。

```json
{"top": [{"station_id": "A01", "passengers": 120}, {"station_id": "A02", "passengers": 98}]}
```

### 4.4 错误码

| HTTP | code | 场景 | message 示例 |
|------|------|------|--------------|
| 400 | `INVALID_PARAM` | 参数类型或范围不对 | `minutes 必须在 1—60 之间` |
| 404 | `NOT_FOUND` | 路径不存在 | `接口不存在` |
| 500 | `INTERNAL_ERROR` | 服务端异常 | `服务端异常` |

```json
{"error": {"code": "INVALID_PARAM", "message": "minutes 必须在 1—60 之间"}}
```

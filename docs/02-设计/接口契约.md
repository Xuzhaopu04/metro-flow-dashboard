## 1. 通用约定

| 项 | 约定 |
|----|------|
| 编码 | UTF-8 |
| 时间 | ISO8601 字符串，精确到毫秒（快照 `ts` 精确到秒），带时区 |
| 时间语义 | `event_time` 是事件发生时间，不是入库时间 |
| 数值 | 人数、条数一律整数 |
| 空值 | `null` |
| 命名 | 小写下划线，前端不做字段名转换 |
| 返回体 | 一律 JSON 对象，不直接返回数组 |
| 错误体 | `{"error": {"code": "...", "message": "..."}}` |

## 2. 消息格式（Redis Stream）

键名 `gate_events`，写入方 `simulator/simulator.py`，消费组 `metric_builder`（`stream/consumer.py`）。
消息体单字段 `data`，值为 JSON 字符串。

### 2.1 闸机事件

| 字段 | 类型 | 必填 | 示例 | 说明 |
|------|------|------|------|------|
| `event_id` | string(uuid) | 是 | `9515820e-...` | 全局唯一，用于去重 |
| `station_id` | string | 是 | `A01` | 站点编码 |
| `line_id` | string | 是 | `L1` | 线路编码 |
| `event_type` | string | 是 | `in` / `out` | 进站或出站 |
| `passengers` | int | 是 | `2` | 本条记录的乘客数，1—5 |
| `event_time` | string | 是 | `2026-10-20T09:30:15.123+08:00` | 事件发生时间 |

### 2.2 异常数据约定

模拟器 `--inject` 会掺两类，消费端**必须处理而不是崩溃**：

| 类型 | 表现 | 期望处理 |
|------|------|----------|
| 缺字段 | 缺 `passengers` 或 `event_time` | 跳过并计入 `invalid_count` |
| 乱序 | `event_time` 早于当前窗口 | 计入 `late_count`，不计入当前窗口 |

## 3. 存储约定

| 键 / 表 | 类型 | 写入方 | 读取方 | 说明 |
|---------|------|--------|--------|------|
| `gate_events` | Redis Stream | 模拟器 | 消费者 | 事件队列，保留最近 10 万条 |
| `metric:snapshot` | Redis String | 消费者 | 接口 | 最新快照 JSON，TTL 5 秒 |
| `metric_window` | MySQL 表 | 消费者 | 接口、对账 | 每站每窗口一行，`(ts, station_id)` 唯一 |

快照结构：

```json
{
  "ts": "2026-10-20T09:30:15+08:00",
  "total": 37,
  "stations": [
    {"station_id": "A01", "line_id": "L1", "passengers": 12},
    {"station_id": "A02", "line_id": "L1", "passengers": 9}
  ],
  "late_count": 1,
  "invalid_count": 0
}
```

### 3.1 告警字段的归属

`metric:snapshot` 只存上面 5 个字段，消费者不写告警。`alerting` 与 `threshold`
由接口层读出后现算并附加到响应（见 4.1）——阈值会变，快照不会。

### 3.2 `metric_window` 表结构（v1.3）

| 列 | 类型 | 说明 |
|----|------|------|
| `ts` | datetime(6) | 窗口起点，UTC 存储 |
| `station_id` | varchar(16) | 站点编码 |
| `passengers` | int | 窗口内乘降量，等于 `in_passengers + out_passengers` |
| `in_passengers` | int | 窗口内进站量，**v1.3 新增**，可空默认 0 |
| `out_passengers` | int | 窗口内出站量，**v1.3 新增**，可空默认 0 |
| `late_count` | int | 该站本窗口迟到事件数 |

迁移策略：先加列（可空默认 0）→ 计算端双写 → 接口切读。加列期间旧消费者照常写
`passengers`，接口读 `in`/`out` 得到 0，不会报错。`(ts, station_id)` 唯一约束不变。

## 4. REST 接口

### 4.1 最新快照

```
GET /api/snapshot
```

成功 200，返回上面的快照结构，并附加两个告警字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `alerting` | boolean | `total >= threshold` 即为 `true`（整站合计，非单站） |
| `threshold` | int | 当前阈值，来自 `ALERT_THRESHOLD`，默认 100 |

前端直接用 `alerting` 渲染横幅，不要在页面写死阈值。

**无数据时也返回 200**，结构如下（不要返回 404）：

```json
{"ts": null, "total": 0, "stations": [], "late_count": 0, "invalid_count": 0, "alerting": false, "threshold": 100}
```

响应头带 `Cache-Control: no-store`。

### 4.2 历史序列

```
GET /api/series?station_id=A01&minutes=5
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| `station_id` | string | 否 | 全部 | 不传则按时间汇总所有站点 |
| `minutes` | int | 否 | 5 | 回溯范围，1—60 |
| `line_id` | string | 否 | 全部 | **v1.3 新增**，如 `L1` |
| `direction` | string | 否 | `all` | **v1.3 新增**，`in` / `out` / `all` |
| `granularity` | string | 否 | `second` | **v1.3 新增**，`second` / `minute` / `hour` |
| `from` | ISO8601 | 否 | — | **v1.3 新增**，起始时间，与 `to` 同时给才生效 |
| `to` | ISO8601 | 否 | — | **v1.3 新增**，结束时间，含该点 |

- `from`/`to` 都给了就用它们，忽略 `minutes`；`to` 缺省为当前时间。
- 跨度上限 24 小时，超出返回 400。`granularity=second` 时点数上限 **2000**，
  超出按等间隔抽稀（保留首尾点），响应里 `truncated` 标为 `true`。
- `direction` 只影响 `in`/`out` 两个分项，`total` 恒为两者之和。

```json
{"station_id": "A01", "line_id": null, "direction": "all", "granularity": "second",
 "truncated": false,
 "points": [{"ts": "2026-10-20T09:30:15+08:00", "in": 7, "out": 5, "total": 12}]}
```

**兼容**：不传新参数时行为与 v1.2 完全一致，`points[]` 仍保留 `passengers`
（等于 `total`），旧前端不改也能跑。

### 4.3 站点排行

```
GET /api/rank?top=5&minutes=5&line_id=L1&direction=all
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| `top` | int | 否 | 5 | 取前 N，1—20 |
| `minutes` | int | 否 | 5 | **v1.3 新增**，统计窗口，1—60 |
| `line_id` | string | 否 | 全部 | **v1.3 新增** |
| `direction` | string | 否 | `all` | **v1.3 新增**，`in` / `out` / `all` |

不传新参数时仍是"最近 5 分钟"，与 v1.2 一致。

```json
{"top": [{"station_id": "A01", "in": 70, "out": 50, "passengers": 120}]}
```

### 4.4 今日汇总

```
GET /api/summary/today
```

**统计起点**：项目时区（`Asia/Shanghai`）当日 00:00:00，不是最近 24 小时。

| 字段 | 类型 | 说明 |
|------|------|------|
| `date` | string | 统计日，`2026-11-17` |
| `since` | string | 起点时间，带时区 |
| `updated_at` | string | 本次查询时间，前端据此判断新鲜度 |
| `total` | int | 今日乘降量合计（进 + 出） |
| `in` | int | 今日进站量 |
| `out` | int | 今日出站量 |
| `net` | int | 净流入，等于 `in - out`，可为负 |
| `peak` | object | `{"ts": ..., "total": ...}`，今日单窗口最大乘降量 |
| `lines` | array | 分线汇总 `[{"line_id": "L1", "in": .., "out": .., "total": ..}]` |
| `top_stations` | array | 分站 TopN `[{"station_id": .., "in": .., "out": .., "total": ..}]`，N 取 5 |
| `quality` | object | `{"late_count": .., "invalid_count": .., "rows": ..}` |

```json
{"date": "2026-11-17", "since": "2026-11-17T00:00:00+08:00",
 "updated_at": "2026-11-17T14:50:03+08:00",
 "total": 12345, "in": 7000, "out": 5345, "net": 1655,
 "peak": {"ts": "2026-11-17T08:32:11+08:00", "total": 143},
 "lines": [{"line_id": "L1", "in": 4000, "out": 3000, "total": 7000}],
 "top_stations": [{"station_id": "A01", "in": 900, "out": 700, "total": 1600}],
 "quality": {"late_count": 3, "invalid_count": 0, "rows": 41233}}
```

无数据时返回同样的结构，数值为 0、数组为空、`peak.ts` 为 `null`。

### 4.5 站点元数据

```
GET /api/stations
```

站名、线路、顺序、坐标、颜色。**只读采集端的 `simulator/stations.json`**，
不在本层复制一份，采集改站点表服务端自动跟随。

| 字段 | 类型 | 说明 |
|------|------|------|
| `stations` | array | `[{"station_id", "name", "line_id", "order", "lng", "lat", "color"}]` |
| `lines` | array | `[{"line_id", "name", "color", "station_ids": [...]}]` |

采集表若缺 `name`/`order`/坐标，对应字段返回 `null`（**不编造**），
`stations[].station_id` 与 `line_id` 来自现表，始终有值。

`lines[].name` 只认采集表里显式的 `line_name` 字段，缺失给 `null`。
**不允许拿某个站点的 `name` 当线路名**——那会把"人民广场"标成 1 号线的名字。
`lines[].station_ids` 按 `order` 升序，无 `order` 时按 `station_id` 升序，
保证同一份表每次请求顺序一致，前端图例不会跳。

### 4.6 错误码

| HTTP | code | 场景 | message 示例 |
|------|------|------|--------------|
| 400 | `INVALID_PARAM` | 参数类型或范围不对 | `minutes 必须在 1—60 之间` |
| 400 | `INVALID_PARAM` | `direction` 取值不在枚举内 | `direction 只能是 in / out / all` |
| 400 | `INVALID_PARAM` | 时间跨度超限 | `时间跨度不能超过 24 小时` |
| 404 | `NOT_FOUND` | 路径不存在 | `接口不存在` |
| 500 | `INTERNAL_ERROR` | 服务端异常 | `服务端异常` |

```json
{"error": {"code": "INVALID_PARAM", "message": "minutes 必须在 1—60 之间"}}
```

## 1. 适用范围口径

skill §1 只覆盖四类分析产物：**用例图、用例表/场景、活动图、域模型（候选关键抽象表 + CRC + 类图 + 对象图）**。
明确排除：详细设计阶段的实现类图、鲁棒图、序列图、状态机、部署图、组件图、数据库表设计、接口文档、界面原型、非 UML 随手流程图。

据此，**"类图"只有在承担领域概念模型职责时才算范围内**；一旦出现数据库字段类型、表名、函数返回值、服务类，就是实现类图，属范围外。这条判据决定了 `10-类图.puml` 的去留（见 §4）。

两条与出图直接相关的规定：

| 规则 | 出处 | 本仓库触发情况 |

| 参与者 ≥4 或用例 ≥8 时禁用自动布局，改坐标化 SVG | 06 §1 | `03-用例图-实时计算`（5 参与者）、`04-用例图-数据服务`（5 参与者）触发，已改为 SVG |

## 5. 处置结论（2026-11-23 定案）

| 编号 | 事项 | 结论与理由 | 落地位置 |
|---|---|---|---|
| A1 | `03`、`04` 把**事件队列（Redis Stream）、指标库（MySQL）、下游模块、快照缓存**画成参与者，与 skill 反模式"把系统内部模块当参与者"冲突 | **保留**。按"模块视角下它们是系统之外、与本模块有交互的协作方"处理，统一标 `«actor»`；优点是能表达模块间依赖，且与用例表角色列表一致。改法二是把 Redis/MySQL 收进边界，会让"谁消费事件"这条依赖从图上消失，信息净损失 | `03`、`04` 两张图；`03-建模/README.md` 说明段 |
| A2 | `14-域模型` 未建模**告警阈值 / 告警事件** | **暂不补类**。阈值当前是前端常量（用例表 UC-17 备选流 A1"待配置化"），还不是业务对象；凭空补两个类等于编造需求。一旦配置化，再补「告警规则」「告警事件」及"触发"关联 | `14-域模型.puml` 头注释第 5 条 |
| A3 | 用例表存在**两套字段集**：UC-01～09、UC-14～18 用 7 字段，UC-10～13 用完整 11 字段 | **本次不扩写**。文件已 17139 字节 / 约 4.3k token，扩到 11 字段约翻倍，会越过 pre-commit 钩子阈值（5000 token / 20000 字节）。正确顺序是先按模块把 `用例表.md` 拆成 4 个文件，再补"描述 / 风险 / 触发条件 / 非功能性需求" | 待办（独立任务） |

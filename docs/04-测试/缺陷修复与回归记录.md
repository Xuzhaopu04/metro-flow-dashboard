## 3. 新增确认时机与补消费

- `read_batch` 增加 `read_id`：正常循环用 `">"`，启动补消费用 `"0"`。
- `CONSUMER_NAME` 默认固定为 `metric-builder`（可在 `.env` 覆盖），重启后仍是同一消费者名，`xreadgroup("0")` 能读到上次未确认消息。
- `drain_pending` 在正常模式启动时执行；遇到 `deferred` 或落库失败立即停止，交给主循环，避免原地打转。
- 回放模式不掺 pending，保持“按样例回填”的语义。

## 4. 验证结果

### 4.1 自动化

用例数从 127 增至 147；新增覆盖见 `docs/04-测试/测试方案与用例.md` 第 8 节。

### 4.2 真实 MySQL（隔离库，验证后已 DROP）

```text
first: True
second: True
rows: [{'station_id': 'A01', 'passengers': 9, 'in_passengers': 8, 'out_passengers': 1, 'late_count': 0}]
quality: [{'late_count': 0, 'invalid_count': 0}]
row_count: 1 quality_count: 1
```

- 结论：同键第二次写入覆盖成功；两张表各 1 行，没有重复。
- 过程中发现 MySQL 后端不接受 `unique_fields`，已按 `connection.vendor` 分支；SQLite 仍显式指定冲突列。

### 4.3 真实 Redis + MySQL（无时区脏数据）

```text
17:27:01 INFO 2026-11-24T17:27:01+08:00 客流 2 站点 1 迟到 0 非法 1
snapshot: {"ts": "2026-11-24T17:27:01+08:00", "total": 2, "stations": [...], "late_count": 0, "invalid_count": 1}
metric_window: [{'station_id': 'A01', 'passengers': 2, 'late_count': 0}]
metric_quality: [{'late_count': 0, 'invalid_count': 1}]
```

- 结论：无时区事件不再打断消费者；非法计数进入质量表；隔离键与隔离库已清理。

### 4.4 真实 Redis + MySQL（deferred 与重启补消费）

```text
第一次 --once：pending = {'pending': 1, 'consumers': [{'name': 'e2e-consumer', 'pending': 1}]}
第二次 --once：启动补消费 → pending = {'pending': 0}
DB：A01 2 人次（17:28:47 窗口）、A02 3 人次（17:28:49 窗口）
```

- 结论：下一窗口事件不再提前 ACK；固定消费者名后重启能补消费；隔离键与隔离库已清理。

### 4.5 真实 MySQL（质量计数混合窗口）

```text
quality: {'late_count': 9, 'invalid_count': 4}
```

- 场景：窗口 A 有 `metric_quality` 行（late=7, invalid=4），窗口 B 只有 `metric_window.late_count=2`。
- 结论：旧窗口的迟到数从 `metric_window` 补回，已覆盖窗口不重复；合计 7+2=9，非法只取质量表 4。

## 5. 未修复 / 留待报告处理

- 固定消费者名只覆盖改版之后的重启；旧版 `worker-{pid}` 遗留的 pending 不会被自动认领。本次真实库 `pending=0`，未做 XAUTOCLAIM。
- 重启补消费只保证“不提前 ACK”；超过迟到容忍（默认 2 个窗口）的 pending 仍按迟到跳过，需要 `--replay` 回补，不能宣称“一条不丢”。
- 事件级去重仍未实现，只在契约里删除了“用于去重”的假承诺；如需事件级幂等，需新增 `event_id` 存储或 Redis 去重键。
- 前端“今日”模式的排行仍取全网 `summary.top_stations`，忽略线路/方向筛选；`queryParams` 的今日起点在 summary 未返回时仍退回浏览器 0 点。
- `DJANGO_DEBUG` 默认仍是 1，默认演示环境下 500 仍是 HTML；`.env.example` 已有“交付前改 0”的提示。
- `deferred` 超限仍会丢弃最早事件，只是不再静默；彻底解决需要回压或持久化 deferred。
- `aggregate_window` 对 `event_time >= window_end` 仍是兜底 `continue`，不计非法；正常流程由 `split_ready` 拦住，未改这个内部约定。
- 报告第三、四部分已统一：3-3/3-8 的正文数字按截图重写，验收线改为 1.2 的计划口径并注明未做连续压测；第四部分表 4-1/4-2 已按真实结果填写；第三部分代码片段已按当前源码替换（`aggregate_window`、`run_window`、`int_param`），其余片段核对一致；第五部分未改。
